# 독립 QoH 현황·변화·성장 신호 어시스턴트 설계 계획서

작성일: 2026-10-16

상태: 사용자와 순차적으로 확정한 요구사항을 정리한 설계 기준. 2026-10-17 설계서 커밋·푸시 후 독립 구현 진행을 승인받았다. 제품 구현, 실제 자료 분석, 회사 보안 승인, 모델 성능 검증이 완료됐다는 의미가 아니다. 구현용 파일 경로·기술 스택은 구현 계획에서 정하며, 사내 API의 구체 사양은 회사에서 확인한다.

## 1. 목적과 성공 기준

입사자가 현재 어떤 역할에서 어떤 기여를 하고 있으며, 어떤 어려움과 변화가 있는지 근거와 함께 파악한다. 조직이 놓칠 수 있는 성장 신호를 먼저 발견하되, 인재 등급·잠재력 점수·순위나 활용·육성 처방은 만들지 않는다.

핵심 질문:

- 입사 시 주목받았던 직원은 확보된 최근 자료에서 어떤 상태인가?
- 현재 역할과 확인된 기여는 무엇이며, 직전 검토 이후 무엇이 달라졌는가?
- 어려움·정체·부정적 변화가 기록됐는가? 그 맥락과 불확실성은 무엇인가?
- 정성적으로 포착한 기여가 이후 자료와 정상 업적평가에서도 인정되는가?

성공은 AI의 유려한 설명이 아니라 담당자가 출처를 확인하며 왜곡·누락을 바로잡고, 현황을 파악해 필요할 때 보고할 수 있는 것이다. 언제든 조회 가능하되 항상 최신 상태를 알고 있다고 표현하지 않는다.

## 2. 적용 범위와 기존 문서 관계

- 독립 모듈이다. CV, JD, 지원자, 선발 건 없이 직원·자료 등록부터 분석·확정·보고까지 가능해야 한다. 향후 연동도 전제하지 않는다.
- 기존 회사 개발 방향이 동등하거나 더 적합하면 유지한다. 문서와 다르다는 이유만으로 재작성·교체하지 않는다. 기능별로 유지/보완/변경 불필요와 이유를 확인한다.
- 2026-10-12 [QoH 인수인계](../../2026-10-12-qoh-hiring-improvement-handoff.md)는 과거 기획 기록으로 보존한다. 본 독립 모듈의 범위가 충돌하는 부분은 이번 사용자 결정으로 대체한다.
- 이전 문서의 필수 채용 개선 목록, 후보자 기준 반영, 조건부 종합점수, 면접 전문 연계, 육성·지원 조치 제안은 이번 버전의 요구사항이 아니다.
- Allnew의 지원자 비교·진행 보고 구현과 혼합하지 않는다. 기존 문서에서 유효한 근거·기간·권한 설계만 참고한다.

제외: CV–JD 연동, 업무공유 툴 연계, 면접·녹음 서비스, 별도 월간·분기 평가 입력, 잠재력·QoH 종합점수, 직원 순위, 슈퍼탤런트 확정, 승계·승진·배치·과제 부여·육성 권고, 자동 인사 판단, 부서장 자동 보고, 미래 성과 예측.

## 3. 대상·사용자·권한

- 초기 대상은 약 3년 전 입사자 중 자료 확보가 가능한 인력이다. 실제 입사 코호트는 등록 시 명시하며 숫자 인원을 강제하지 않는다.
- 재직자뿐 아니라 전배·퇴사자도 자료와 열람 권한이 있으면 포함한다. 자료가 있는 기간까지만 분석한다. 이동·퇴사 자체를 부정 신호로 삼지 않는다.
- 일부 자료가 없어도 등록할 수 있다. 모든 자료를 갖춘 사람만 선별하지 않는다. 분석 범위·누락 기간을 표시하고 표본을 회사 전체 성공률로 일반화하지 않는다.
- 사번을 식별·연결 기준으로 사용한다. 이름 유사도로 연결하지 않는다. 사번 미확인·충돌 자료는 해결 전 분석에서 제외한다.
- 첫 버전 원문·AI 초안·분석·검토 이력은 지정 HR 담당자만 열람한다. 지정 범위 밖 사용자는 서버에서 접근을 차단한다.
- 부서장에게는 담당자가 검토·확정한 보고만 필요시 전달한다. 부서장용 직접 열람 계정·자동 발송은 필수가 아니다.
- 담당자의 근거 확인은 원문의 진술을 확인한 것이며, 실제 사실이나 미래 가능성을 보증하는 행위가 아니다.

## 4. 입력과 원자료 조회

| 자료 | 주기·처리 |
|---|---|
| 채용 시 활용계획서 | 최초 기대의 참고 기준. 변경본은 별도 보존 |
| MBO | 통상 연 1회 수립. 목표·과제이며 그 자체로 달성 증거가 아님 |
| 업적평가와 부서장 등급 부여 코멘트 | 통상 연 1회. 등급과 인정 사유를 함께 분석 |
| 수시 피드백 | 연간 횟수 미확정. 2회·3회로 고정하거나 예상 횟수 누락을 오류 처리하지 않음 |

- 엑셀·PDF·워드·복사한 텍스트가 섞인 입력을 허용한다. 통일 양식 재작성은 요구하지 않는다. 정확한 확장자 지원은 구현 전 시험으로 확정한다.
- 원본, 추출본, 담당자 정정본을 구분한다. 복사한 텍스트도 등록 내용과 등록 시점·자료 출처 설명을 보존한다.
- PDF는 페이지·구간, 엑셀은 시트·셀 범위, 워드는 문단·표 위치, 텍스트는 구간으로 추적한다. 실제 도구가 위치를 보존할 수 있는지 검증한다.
- 표 구조·평가등급·코멘트 연결을 보존한다. 추출 실패와 원문에 내용이 없는 상태를 구분한다.
- 스캔본 OCR은 회사 승인 도구·환경에서만 처리한다. 승인 도구가 없으면 해당 자료를 처리 불가로 표시하고 부분 분석 원칙을 적용한다.
- 사번, 자료 유형, 대상 기간, 작성일을 추출한다. 기간이 불명확하면 임의 추정하지 않고 확인 요청한다. 작성일·등록일·성과 대상 기간은 별도 필드다.
- 중요 주장 옆에서 해당 원문을 직접 조회한다. 출처가 존재한다는 것과 주장을 지지한다는 것은 별도 확인 대상이다.

## 5. AI-native 분석 흐름

자료 여러 건 등록 → 식별·추출 결과 및 공백 표시 → 담당자 ‘분석 시작’ → 직원별 AI 분석 → 중요 항목 근거 검토 → 직원별 확정 → 필요시 현황 보고.

1. 자료 업로드만으로 분석·재분석하지 않는다. 등록 단계의 파일 검사·추출과 본 분석 실행은 구분한다.
2. 분석 시작 시 입력 자료 버전 목록, 대상 직원, 현재 확정본 ID를 실행 단위로 고정한다. 실행 중 추가 자료는 다음 분석 대상이다.
3. AI가 먼저 기여·어려움·성장 신호·변화와 근거를 정리한다. 사람이 먼저 정답지나 독립 분석 보고서를 작성하도록 요구하지 않는다.
4. 직원별 처리 결과를 분리한다. 한 직원의 실패가 다른 직원의 분석·검토를 막지 않는다. 실패 직원만 재시도하고 중복 결과 생성을 방지한다.
5. 일부 자료 실패 시 성공 자료로 만든 부분 초안은 표시할 수 있다. 실패·미처리 자료와 영향을 명시하며 전체 자료를 완료한 것으로 표시하지 않는다.
6. 담당자가 범위를 인지하고 확정하더라도 부분 자료라는 표시는 현황·보고에 남긴다. 영향 범위를 알 수 없는 중요한 주장은 보류한다.
7. 사내 AI가 추출·비교·설명 초안을 작성한다. 사번·기간 검증, 권한, 상태 전이, 버전, 중복 처리 등 결정론적 통제는 프로그램이 담당한다.

정기 자동 분석·메일·메신저가 아니라, 수동 실행 후 AI가 질문을 기다리지 않고 주요 변화를 제시하는 선제성이다. 새 자료 없는 기간에 새로운 인사이트를 꾸며내지 않는다.

## 6. 현황·변화 해석 원칙

- 최초 활용계획은 정답이나 고정 평가기준이 아니다. 최초 기대, 현재 합의 역할·목표, 새롭게 관측된 기여를 구분한다.
- 계획과 달라도 다른 영역에서 유의미한 기여가 있으면 그대로 보여준다. 변경 자체를 저성과로 해석하지 않는다.
- 개인 역할과 팀 성과, 목표와 실적, 원문 사실과 평가자 의견·AI 해석을 분리한다.
- 과제 배정·장비·협업·목표 변경 등 기록된 맥락을 병기한다. AI가 어려움의 원인을 개인 역량으로 단정하지 않는다.
- 같은 사건을 평가·피드백에서 반복 언급해도 독립 근거 여러 건으로 계산하지 않는다.
- 긍정·부정 모두 구체적인 상황·행동·기여·결과가 있는지 본다. ‘우수하다/기대된다’, ‘아쉽다/적극성이 부족하다’만 있으면 의견·구체적 근거 부족으로 분류한다.
- 자료 부족은 저성과, 성장 가능성 부족, 변화 없음과 다르다. 기간별 자료 범위를 명시한다.
- 서로 다른 평가제도·평가자·업무 기회를 숨긴 단순 비교·점수 환산을 하지 않는다.

## 7. 첫 정상평가와 성장 신호

### 7.1 평가 구분

사용자 확인: T는 비정상평가 표시이고, T가 아닌 유효한 공식 평가 중 시기상 첫 평가가 첫 정상평가다. EM·ES는 정상평가의 상위 등급이다.

| 이력 | 해석 |
|---|---|
| T → EM | 첫 정상평가 EM, 첫 정상평가 상위 |
| T → ES | 첫 정상평가 ES, 첫 정상평가 상위 |
| T → MT → EM | 첫 정상평가 MT, 이후 상위 평가 획득 |

- T → EM/ES를 점수 상승이나 성과 향상으로 계산하지 않는다. T를 제외한 정상평가에서 상위를 확인한 사건으로 처리한다.
- 빈값·알 수 없는 문자열·추출 오류를 ‘T가 아니므로 정상평가’로 인정하지 않는다. 회사에서 확인된 유효 코드·확정 상태만 사용한다.
- 평가 순서는 파일 등록일이 아니라 실제 평가 대상 기간·공식 순서로 판단한다. 과거 이력 누락 시 확보 자료 중 최초와 실제 첫 정상평가를 구분해 확인 필요로 둔다.
- 정정은 동일 평가 사건의 새 버전으로 기록한다. 다음 평가를 임의로 첫 정상평가로 바꾸지 않는다.
- 과거 등급을 포함한 전체 코드·제도 대응은 회사에서 재확인한다. 기존 문서의 매핑을 이번 승인으로 간주하지 않는다.

### 7.2 정성적 기여와 후속 확인

- 정량 실적이 아니어도 구체적 기여가 확인되면 성장 신호 후보로 제시한다. 기술문제 해결·성과 재사용·책임 범위 확대 등은 예시이지 필수 입력이나 자동 가점 조건이 아니다.
- 첫 정상평가 상위는 한 발견 경로다. 상위 평가가 없는 직원과 장기 연구 인력도 구체적 기여로 발견 가능해야 한다.
- 잠재력 숫자나 순위 대신 ‘첫 정상평가 상위’, ‘새로운 기여 확인’, ‘이후 평가에서 기여 인정’과 근거·기간을 보여준다.
- 정성 신호는 해당 기여 기간을 포함하는 다음 정상 업적평가 확정 시 재검토한다. 그전에도 새 자료가 있으면 갱신한다.
- 등급뿐 아니라 부서장의 등급 부여 코멘트에서 해당 기여가 어떻게 인정·설명됐는지 대조한다. 상위 등급만으로 특정 신호가 검증됐다고 간주하지 않는다.
- 이후 상위 평가와 관련 기여 인정이 있으면 신호를 보강한다. 비상위라도 구체적 산출물·기여가 추가 확인되면 담당자가 유지 여부를 검토한다.
- 칭찬만 반복되고 구체적 근거가 보강되지 않으면 추가 확인 필요로 제시하고, 담당자 검토 후 반복 강조를 줄인다. 평가 코멘트의 미언급만으로 기여를 부정하지 않는다.
- 보정 대상은 직원 점수가 아니라 신호의 근거 수준·현재 해석·노출 강도다. 자동 감점·자동 소멸은 없다.
- 관측 기간, 후속 확인 상태, 마지막 자료 시점을 표시한다. 자료가 없으면 후속 관측 없음이지 부정 변화가 아니다.
- 현재 성과로 미래 전문가·리더 적합성을 확정하지 않으며 연령·학위로 가점·제외하지 않는다.

## 8. 담당자 검토·확정과 비교 기준

- 중요 항목은 성장·어려움·정체·인식에 영향을 주는 변화다. 각 항목에 근거, 대상 기간, 사실/의견/해석, 반대·보완 자료, 미확인 내용을 붙인다.
- 담당자는 항목별로 근거 확인/수정/보류/제외한다. 일반 자료 정리에는 문장별 승인을 요구하지 않는다.
- 한 줄 요약·변화 제목도 중요 해석을 포함하면 검토 대상이다. 미검토 해석을 일반 요약으로 우회해 보고하지 않는다.
- 사용·실패·제외 자료 목록과 기간을 함께 제공하고, 담당자가 누락된 기여·어려움을 추가할 수 있게 한다. 사람 수정도 출처 또는 담당자 해석 표시가 필요하다.
- 직원 단위 상태는 초안/검토 중/확정으로 구분하며 부분 자료 여부는 별도 표시다. 중요 미검토 항목이 있으면 확정을 막는다. 보류·제외 항목은 이유를 남기며 보류 항목을 확정된 주장으로 보고하지 않는다.
- 새 분석의 비교 기준은 마지막 담당자 확정본이다. 처음은 변화가 아닌 확보 범위의 현황을 보여준다.
- 원본·추출본·AI 초안·담당자 수정본·확정본을 구분한다. 새 초안은 확정본을 덮어쓰지 않는다.
- 실행 중 다른 확정본이 생기면 오래된 비교 기준임을 표시하고, 최신 기준으로 재검토하기 전 확정을 막는다. 이는 구현 시 검증할 안전 기본안이다.
- 원자료가 정정·삭제되면 영향받는 결과를 재확인 필요로 표시한다. 과거 확정본을 몰래 수정하거나 근거가 유효한 것처럼 재사용하지 않는다.

## 9. 화면·보고·추가 질문

### 기본 화면

1. 주요 변화: 새 기여·성장 신호와 어려움·정체·부정 변화를 함께 표시한다.
2. 전체 현황: 등록 대상 전원을 조회한다. 변화 없음과 최근 자료 부족을 구분한다.
3. 직원 상세: 현재 역할·기여·어려움, 평가와 피드백 이력, 원문, 신호의 후속 상태, 입사 후 전체 이력.
4. 검토 화면: AI 주장과 원문을 나란히 대조하고 확인·수정·보류·제외한다.

### 필요시 보고

담당자가 직원·항목을 선택하면 현재 역할·확인된 기여 / 주요 변화 / 성장 신호와 후속 확인 / 자료 기준일·출처·미확인 사항으로 초안을 만든다. 어려움도 포함한다. 육성·지원·배치 처방은 생성하지 않는다.

- 담당자 확정 내용만 사용하고, 보고 초안도 담당자가 최종 확정한다. 자동 발송하지 않는다.
- 공유 대상에 맞는 최소 정보만 담는다. 원문 전체·미검토 초안·내부 검토 의견을 자동 첨부하지 않는다.
- 보고 UI·다운로드 형식·전달 경로는 회사 환경에서 결정한다. 이번 설계가 메일·메신저 연동을 승인하지 않는다.

### 추가 질문

저장된 원자료와 검토 이력에 대해 출처를 붙여 답한다. 미검토 원문 기반 답변과 확정된 현황을 구분한다. 추가 질문 응답은 확정본을 자동 수정하지 않으며 보고 입력으로 자동 편입하지 않는다. 근거가 없으면 알 수 없다고 답한다.

## 11. 사내 AI API·보안·실패 처리 경계

- 실제 분석 모델은 회사 승인 사내 AI API를 사용한다. 대화 중 가우스·카오스 명칭이 혼용되어 정확한 명칭은 회사에서 확인한다. 버전·입출력 한도·구조화 응답·파일 처리·인용 기능은 아직 검증하지 않았다.
- 모델 호출부와 자료·검토·권한 로직을 분리한다. 모델이 반환한 사번·등급·출처·상태를 검증 없이 신뢰하지 않는다.
- 긴 자료 분할 시 직원·기간·출처 연결을 유지하고 누락을 기록한다. 모델 입력 한도로 잘린 자료를 전부 읽었다고 표시하지 않는다.
- 문서 안 지시문은 자료이며 시스템 명령이 아니다. 임의 외부 접속·권한 변경·자료 공개를 유도하는 내용을 실행하지 않는다.
- 오류·시간초과·응답 형식 실패는 분석 불가로 표시한다. 직원의 부정 상태로 변환하지 않는다. 모델이 성공했다고 반환해도 출처·응답 계약을 검증한다.
- 비인가 조회, 직원·기간 오연결, 허위 인용 발견 시 관련 결과의 확정·공유를 차단한다.
- 원문 저장 가능이라는 사용자 확인과 회사의 저장·처리 정책 승인은 구분한다. 사내 AI라고 보안 검토가 생략되지는 않는다.
- 회사 승인 저장소·전송 경계, API 입력·응답 로그, 학습 재사용, 보존·삭제, 백업, 접근 감사는 실제 자료 사용 전 확인한다. 무기한 보존을 기본값으로 두지 않는다.
- 직원 원자료·사번·회사 API 주소·인증정보는 개인 GitHub·외부 에이전트·일반 오류 로그로 보내지 않는다. 공개 개발 자료는 합성 데이터만 사용한다.

## 12. 개발 순서와 수용 기준

이 절은 설계 수준의 순서이며 코드 구현 승인이나 완료 일정 약속이 아니다.

1. 독립 구현의 실행 환경과 재사용 가능한 기반을 확인한다. 회사 최신 구현·실제 자료·사내 AI 보안 조건은 회사 인수 단계에서 확인한다.
2. 직원·혼합 자료 등록, 사번 연결, 추출·원문 조회·실패 표시를 완성한다.
3. 수동 일괄 분석, 직원별 부분 성공·재시도, 근거 연결과 신호 분류를 구현한다.
4. 중요 항목 검토, 직원별 확정·버전·직전 확정본 비교를 구현한다.
5. 주요 변화·전체 현황·보고 초안·추가 질문을 구현한다.
6. 실제 회사 승인 환경에서 자료 등록부터 검토까지 사용하며 오류·누락·부담을 확인하고 대상 범위를 확대한다. 사람의 사전 정답지 작성을 필수로 하지 않는다.

| 검증 사례 | 기대 결과 |
|---|---|
| T → MT → EM | 첫 정상평가 MT, 이후 상위 평가 획득. T를 점수로 비교하지 않음 |
| 코드 미상·과거 평가 누락 | 정상평가·최초 여부를 임의 확정하지 않음 |
| 다른 영역에서 기여 | 최초 계획 이탈만으로 부정 신호를 만들지 않음 |
| 칭찬·비판만 있는 코멘트 | 방향에 관계없이 구체적 근거 부족으로 구분 |
| 목표만 존재·팀 성과만 존재 | 개인의 성과 달성으로 변환하지 않음 |
| 같은 기여가 여러 자료에 반복 | 중복을 독립 검증으로 세지 않음 |
| 정성 기여 후 상위 평가 | 관련 기간·등급 부여 사유를 대조한 뒤 신호 보강 검토 |
| 비상위 평가·미언급 | 기존 기여를 자동 부정·삭제하지 않음 |
| 일부 자료·직원 분석 실패 | 범위 표시, 해당 직원만 재시도, 다른 직원 검토 지속 |
| 새 자료 없음 | 새 변화 생성·자동 하향 없음. 후속 관측 없음 표시 |
| 중요 해석 미검토 | 일반 요약·추가 질문을 경유해 보고에 포함되지 않음 |
| 재분석·동시 확정 | 확정본 보존, 비교 기준 충돌 표시, 직원별 확정 가능 |
| 원문 정정·삭제 | 영향받는 결과 재확인·공유 제한 |
| 비인가·외부 노출 유도 문서 | 서버 권한 검사, 외부 전송·명령 실행 차단 |
| 보고 생성 | 담당자 확정 현황만 사용, 육성 처방·자동 발송 없음 |

검증은 결정론적 단위·통합 테스트와 회사 자료의 실제 검토를 분리한다. 허위 인용·직원 오연결·중요 누락·근거 부족 단정·검토 시간·수정 부담을 기록하되, 근거 없는 정확도·예측력·토큰 절감 수치를 제시하지 않는다. 사내 모델 업데이트 시 같은 합성 경계 사례를 다시 확인한다.

### 개발·회사 인수 분담

- 여기서는 기존 채용 프로그램과 별개로 실행 가능한 독립 프로그램, 영속 저장, 자료 조회, 검토·확정·보고·추가 질문과 테스트를 개발한다. 다른 기술탭과 별도 작업 공간·브랜치로 분리한다.
- AI 연결은 모델 중립적인 요청·응답 계약과 교체 가능한 어댑터로 분리한다. 합성 자료와 테스트용 응답으로 실제 저장·조회·검토 흐름을 검증한다. 사내 API를 OpenAI 호환으로 가정하거나 회사 인증 방식을 임의 구현하지 않는다.
- 회사에서는 승인된 환경 설치·운영 설정, 실제 사내 AI 어댑터 연결·인증, 기존 입사자 자료 등록, 추출·분석 품질과 보안 검증을 수행한다.
- 테스트용 어댑터는 명시적으로 표시하고 합성 자료 전용으로 제한한다. 미연결 상태에서 규칙·테스트 응답을 실제 AI 분석인 것처럼 제공하지 않는다.
- 회사 API 연결은 핵심 자료·검토 로직을 다시 만드는 작업이 아니어야 한다. 다만 실제 모델의 한도·형식에 따른 어댑터, 프롬프트·분할 조정과 실데이터 검증은 남는다. 연결만으로 분석 품질을 보장하지 않는다.
- 자료 전체가 메모리나 브라우저 저장소에만 머무르는 데모는 독립 실행본의 완료 기준을 충족하지 않는다. 재시작 후 원문·결과·검토 이력이 유지돼야 한다.

## 13. 구현 전 확인할 항목과 문서 검토

회사 최신 코드·배포 환경, 사내 AI API 사양·한도·승인 범위, 실제 파일 형식·OCR 지원, 전체 평가 코드·확정 규칙, 지정 HR 범위, 보존·삭제·백업 정책, 보고 전달 방식은 미확인이다. 이 확인을 이유로 이미 확정한 제품 방향을 다시 광범위하게 질문하지 않는다. 사내 API·실제 자료가 없다는 이유로 독립 프로그램의 합성 검증 가능한 구현을 중단하지 않는다.

문서 검토 관점:

- 요구사항: 독립성, 현황 중심, 긍정·어려움 대칭, 수시 피드백 횟수 미고정, 육성 처방 제외.
- 실행 가능성: 혼합 문서 위치 추적, T·미상 코드 구분, 부분 실패, 직원별 확정·기준본 충돌.
- 통제·효율: AI 우선 분석, 중요 항목 집중 검토, 원문 대조, 권한·최소 공유, 근거 없는 자동 판단 방지.

이번 문서는 일반화된 요구사항만 담는다. 승인된 작업 순서는 이 설계서만 문서 브랜치에 커밋·푸시한 뒤 독립 작업 공간에서 구현 계획을 작성하고 구현·검증하는 것이다. 기존 문서·기존 제품 코드·기존 기술탭·main은 변경하지 않는다. 이번 문서 공개 승인은 실제 직원 자료·사내 API 정보 공개나 구현 코드의 자동 푸시·PR·병합 승인이 아니다.
