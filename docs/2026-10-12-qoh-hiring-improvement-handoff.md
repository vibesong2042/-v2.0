# QoH 기반 채용 개선: 회사 개발 인수인계

작성일: 2026-10-12

상태: 사용자 검토와 그리팅 가이드북 재검토를 반영한 개발 요구사항. 이 커밋은 문서만 추가하며 QoH 구현·실제 분석·점수 타당성 검증 완료를 뜻하지 않는다.

## 1. 목적과 실행 경계

채용 당시 기대, 실제 맡긴 업무, 입사 후 관측 기여를 연결해 인력 활용·지원과 다음 채용의 기준·질문·검증 방법을 개선한다. 직원 평가 요약만 제공하거나 성과를 보고 과거 채용을 사후 합리화하는 기능으로 끝내지 않는다.

- 회사 개발본은 실제 자료와 사내 AI를 사용하는 실전용 개발이라는 사용자 설명을 전제로 한다. 현재 회사 기능·승인·자료 품질을 이 작성자가 검증하지 않았다.
- 초기 대상은 소규모 과거 경력입사자 사례군이다. 학위는 경력 맥락이며 자동 가점·대상 제외·시드인재 지정 조건으로 사용하지 않는다.
- 기존 [회사 연동 경계](rolefit-company-integration.md), [고위험 검토 기준](rolefit-high-risk-review-harness.md), [운영 준비 항목](production-readiness-gates.md)을 회사 최신 정책과 대조한다. 공개 초기 Mock 상태를 회사 버전의 상태로 단정하지 않는다.
- 회사 현재 코드에 이미 충족된 기능은 유지한다. 초기 코드로 되돌리거나 별도 프로젝트의 기능을 이 저장소에 혼합하지 않는다.
- 실제 직원 평가·목표·피드백·면접 자료와 회사 전용 코드·연동 정보는 승인된 회사 환경에만 둔다. 가명 ID도 회사에서 재식별 가능한 정보이며 공개 테스트 자료로 쓰지 않는다.

## 2. 참고 근거와 채택 범위

참고: 그리팅 채용연구소, `[그리팅] 채용 퀄리티(QoH) 관리 가이드북`.

이 문서에서는 원본 PDF 34페이지를 재검토했다. 일부 PDF 페이지는 인쇄본 두 면을 포함한다. 아래는 인쇄 번호이며 원본 PDF는 이 저장소에 업로드하지 않는다.

| 근거 | 채택할 방향 |
|---|---|
| 인쇄 12~16쪽 | 채용 전, 입사 초기 적응, 장기 기여의 시점 구분. 조직별 지표 선택 |
| 인쇄 17~20쪽 | 상위·하위 가중치와 정규화 점수 접근. 산식은 그대로 복사하지 않고 별도 확정 |

| 인쇄 52~56쪽, 실패 사례 | 기대와 실제 환경 차이, 피드백·온보딩 지원을 함께 점검 |

가이드북의 기업 인터뷰는 운영 사례이며 인과 효과·보편적 예측력의 증명이 아니다. 소개 문구·잠재력·문화 적합성 표현을 자동 직원 판단이나 후보자 판정 기준으로 가져오지 않는다.

## 3. 자료와 지표의 연결

| 자료 | 먼저 추출할 내용 | 이 자료만으로 확정하지 않을 내용 |
|---|---|---|
| 채용 시 활용계획서 | 채용 목적, 기대 역할·산출물·시점, 필요한 지원 | 실제 역량 검증 기록 |
| 입사 후 공식 평가 | 평가 기간, 기존 등급·점수·기준, 근거와 변화 | 평가자·연도 간 자동 비교 가능성 |
| 입사 후 업무목표 | 실제 과제, 목표·기한·변경, 활용 역할 | 목표 문서만으로 달성 여부 |
| 부서장 수시 피드백 | 작성 시점, 관측 사실, 의견, 강점·어려움·지원 요청 | 직원 본인의 몰입·만족, 다면 평가 |
| 당시 CV·면접·채용 결정 사유, 확보 시 | 당시 확인 가능한 단서와 확인한 범위 | 자료가 없는 질문·답변을 AI로 재구성 |
| 재직·전배·퇴사 기록, 확보 시 | 기간·상태·변동 및 확인된 사유 | 재직 여부만으로 채용 성공·실패 |

초기에는 업무 성과·기대 기여·매니저 관측을 중심으로 시작한다. 직원 참여도·초기 적응·생산성 도달 시간·유지/이직은 해당 시점의 자료가 있을 때만 측정한다. 현재 자료로 과거 초기 상태를 추정해 채우지 않는다.

## 4. 기대 기준과 시간축

### Q1. MOC형 기대 기준

- Mission: 왜 채용했고 어떤 조직 과제에 기여하기를 기대했는가.
- Objective: 기대 산출물, 확인 시점, 성공 조건은 무엇인가.
- Competency: 그 결과에 필요한 역량을 당시 어떻게 확인했는가.
- 지원 조건: 장비·데이터·교육·협업·과제 배정 등 성과를 가능하게 하는 조건.

과거 활용계획이 모호하면 모호함 자체를 기록한다. 현재 관점으로 재구성한 기대는 사후 재구성으로 표시하고 채용 당시 합의된 기준과 구분한다.

### Q2. 시점별 분석

- 직원 내부 ID, 업무·역할, 평가 기간, 자료 버전·작성 시점과 출처 구간을 연결한다.
- 초기 기대와 변경된 기대를 별도로 보존한다. 과제·배치·기준 변경 시점을 기록한다.
- 공식 평가값, 관측된 산출물, 평가자 의견, AI 해석을 분리한다.
- 3년치 자료를 한 덩어리로 합치거나 최신 평가로 모든 기간을 대표하지 않는다.
- 동일 사건이 목표·평가·피드백에 반복돼도 독립 증거로 중복 계산하지 않는다.

## 5. 두 개의 필수 결과물

### Q3. 활용·기여 관측 카드

개인별 카드의 최소 내용:

1. 채용 목적과 기대 역할·산출물.
2. 실제 업무목표·과제 및 변경.
3. 관측 기여·기간별 공식 평가와 근거.
4. 기대 대비 차이 및 과제·배치·지원 맥락.
5. 다른 가능한 설명과 추가 확인 사항.
6. 사람의 확인·반박·보류와 다음 활용·지원 조치.

모든 중요 문장은 출처로 대조할 수 있어야 한다. 자료 공백은 미측정/판단 불가로 표시한다. 높은 평가를 개인의 모든 역량 확인으로, 낮은 평가를 채용 실패로 자동 변환하지 않는다.

### Q4. 다음 채용 개선 발견 목록

발견 한 건에 다음 정보를 기록한다.

| 항목 | 계약 |
|---|---|
| 관측 | 기간·역할·출처가 있는 기여 또는 어려움 |
| 당시 단서 | 당시 자료에 존재한 내용 / 당시 확인 기록 / 입사 후 새 관측 / 자료 부족 |
| 해석 | 채용 확인, 활용·배치, 지원, 추가 확인 중 무엇을 검토할지와 대안 설명 |
| 개선안 | JD 요건, 공통 질문·과제, 본인 역할·성과 조건, 활용·지원 합의 중 구체적인 변경 |
| 근거 상태 | 자료로 확인 / 현업 확인 / 검토 가설 / 판단 불가 |
| 적용 상태 | 제안 / 검토 중 / 승인 / 보류 / 폐기 |
| 적용 범위 | 승인한 직무·선발 건·기준 버전·적용 시점·책임자 |

채용담당자·현업이 승인한 개선안만 이후 채용 기준에 반영한다. 사람 간 의견 차이는 자동 평균이나 AI 확정으로 없애지 않는다. 같은 선발의 후보자에게 동일 적용하며 진행 중 기준을 조용히 바꾸지 않는다.

원 직원의 평가·피드백을 후보자 화면에 전달하지 않는다. 승인을 거쳐 일반화한 직무 관련 기준·질문만 재사용한다. 좋은 성과자의 학교·배경·문체·유사성을 새 후보자 자동 가점·제외 기준으로 만들지 않는다.

## 6. 점수와 가중치의 조건부 설계

QoH의 측정·관리 기능을 포함한다. 점수를 일괄 금지하지 않지만 첫 구현에서 종합점수를 억지로 만들지 않는다.

- 공식 평가값은 원래 척도·기간·출처를 보존한다. AI가 자유서술을 읽고 직원 점수를 임의 생성하지 않는다.
- 정규화와 상위·하위 가중치, 포함 지표는 회사에서 승인한 버전의 지표 정의서를 사용한다. 승인 전에는 영역별 관측과 공식 평가만 표시한다.
- 모든 필요한 지표가 있고 비교 조건이 맞을 때 승인된 종합점수를 산출한다. 미측정은 0점이 아니다.
- 일부 지표만 있는 경우 측정 범위·누락을 표시한다. 별도 승인 없이 남은 가중치를 자동 재배분하지 않고 전체 종합점수 산출을 보류한다.
- 점수 상세에서 원값, 환산, 가중치, 계산 과정, 포함·제외와 기준 버전을 확인할 수 있어야 한다.
- 채용 전 평가와 사후 기여는 별도 저장·표시한다. 후보자 선발과 사후 검토를 같은 확률로 표현하지 않는다.
- 채용 전 평가를 포함한 종합점수로 그 평가의 사후 예측력을 입증하지 않는다.

가이드북 산식 적용 전 확인 사항:

1. 인쇄 18쪽 매니저 만족도는 상위 15%, 유일한 하위 항목도 15%다. 이중 곱 시 실효 비중은 2.25%이며, 전 항목 100점의 예시 전체 최대값은 87.25점이다. 표기 의도를 임의 확정하지 말고 회사 지표 정의에서 상위·하위 합계와 중복 적용을 명확히 한다.
2. 생산성 도달 시간이 업무 성과와 참여도 양쪽에 포함된다. 의도적 중복인지 확인하고 이중 계산을 설명한다.
3. 문화 적합성은 호감·성격·충성도 추정 대신 직무 관련 협업·지식 공유 등 관측 행동으로 정의한다. 직원 참여도는 매니저 만족도와 같은 지표로 대체하지 않는다.

점수 산식이 추가되면 만점·최소값·경계·누락·가중치 합계·중복·기준 변경을 결정론적 테스트로 확인한다. 직원 자동 순위·성과 예측·자동 인사 판단은 이번 범위 밖이다.

## 7. 소규모 사례 분석의 한계와 통제

- 사례군 선정 기준과 전체 대상 수, 확보·미확보 자료를 표시한다. 현재 재직자만 분석하면 퇴사·전배 사례 제외를 명시한다.
- 서로 다른 역할·과제·평가자·연도 조건을 숨긴 단일 순위나 평균을 만들지 않는다. 표본 수가 작은 집계에는 분모와 자료 범위를 표시한다.
- 사후 결과를 보기 전에 당시 자료의 기대·근거·확인 공백을 먼저 정리한다. 가능하면 초기 검수에서 사후 평가를 가린다.
- 중요한 발견은 현업이 출처·맥락을 검수한다. 개인 평가는 채용 예측의 자동 정답이 아니다.
- 과거 사례에서 만든 개선안은 잠정 가설로 시작한다. 새 채용에서 사용·확인 결과를 기록하고 검토 후 유지·수정·폐기한다.
- 작은 사례군으로 전체 성공률·인과 효과·성과 예측 정확도를 주장하지 않는다.

## 8. 면접 전문: 향후 자료 연결

- 다음 면접부터 제공되는 텍스트를 추가 입력으로 연결한다. 과거 사례 분석의 필수조건으로 만들지 않는다.
- 질문·답변·요건, 화자·시점·출처와 사람의 판정을 연결한다. 화자 구분이 불명확하면 확인 필요로 표시한다.
- 전사 정정은 원본과 분리해 보존한다. 자동 전사 오류를 후보자의 답변 오류로 확정하지 않는다.
- 녹음·전사·AI 처리·보관·열람은 회사의 승인·고지 절차와 권한 안에서 수행한다.
- 말투·억양·감정·성격·충성도를 분석하거나 점수화하지 않는다. 녹음·전사 서비스 자체 구현은 이번 주 필수 범위에서 제외한다.

## 9. 이번 주 개발 순서와 수용 기준

### 개발 순서

1. 회사 최신 코드, 자료 접근·AI 전송·평가 정보 권한과 입력 자료의 기간·공백을 확인한다.
2. 대표 사례의 Q1~Q3 자료·출처 연결과 현업 검수 흐름을 완성한다.
3. Q4 발견 목록과 제안·검토·승인·보류를 구현한다.
4. 대표 사례의 오류·검수 부담을 확인한 뒤 승인된 전체 사례군으로 확대한다.
5. 지표 정의가 승인·확보된 경우에만 조건부 점수 계산을 추가한다. 범용 인재관리·성과 예측·대규모 대시보드는 후속으로 둔다.

### 수용 기준

| 사례 | 기대 결과 |
|---|---|
| 목표만 있고 산출물·평가 없음 | 목표 존재와 달성 미확인을 분리 |
| 당시 자료 없음 | 놓친 채용 검증을 확정하지 않고 자료 부족 표시 |
| 실제 과제와 활용계획 불일치 | 변경 이력·지원 맥락과 대안 설명 제공 |
| 같은 사건이 여러 자료에 반복 | 중복 관측 표시, 독립 증거·점수 중복 금지 |
